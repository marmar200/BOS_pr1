# pr1

Программа копирует данные в стандартный поток вывода. По назначению она совпадает с утилитой `cat`: печатает содержимое указанных файлов друг за другом. Если файлы не переданы, читает стандартный ввод.

## Функционал

Программа разбирает аргументы командной строки и для каждого существующего файла вызывает `filecopy`. Эта функция читает вход по одному байту (`getc`) и сразу записывает его в выход (`putc`).

- Без аргументов содержимое stdin копируется в stdout. Так программа работает в конвейере и при перенаправлении ввода.
- С одним или несколькими путями файлы открываются по очереди и их содержимое выводится в том же порядке.
- Если файл открыть не удалось, в stderr печатается сообщение `can't open`, и программа завершается с кодом `1`. Файлы, которые идут в списке после ошибочного, уже не обрабатываются.
- Если при записи в stdout возникает ошибка, в stderr печатается `error writing stdout`, код завершения — `2`.
- Успешное завершение возвращает код `0`.

## Ввод

- Аргументы командной строки: пути к файлам, которые нужно вывести.
- Стандартный ввод: используется только когда путей нет.

## Вывод

- Стандартный вывод: неизменённое содержимое файлов или стандартного ввода.
- Стандартный поток ошибок: сообщения о сбое открытия файла и о сбое записи.

## Сборка

Нужны `gcc`, `make` и `bash`. Сборка создаёт каталог `.build` и исполняемый файл `.build/program`. Эти файлы в репозиторий не входят.

```bash
make
./.build/program file1.txt file2.txt
printf 'hello\n' | ./.build/program
make clean
```

## Аналог в Linux

Ближайший аналог — утилита [`cat`](https://man7.org/linux/man-pages/man1/cat.1.html). Она так же выводит файлы в stdout и читает stdin, если имена файлов не заданы.

Отличие от GNU `cat`: эта программа останавливается на первом файле, который не удалось открыть. `cat` сообщает об ошибке и продолжает обработку остальных аргументов.
